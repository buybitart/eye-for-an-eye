# Trusted Final-decision Evaluation

**Date:** 2026-09-12
**Required by:** P15.1 §5–§9
**Method:** replay a trusted labelled corpus through the complete system, to the
final ALLOW / TEMP_BLOCK, and measure the action rather than the score.

---

## The Headline

**The system blocked nothing.** Not one source, not one window, across 7,576
observation windows from 709 distinct sources including 144 controlled scanners,
credential-automation runs and protocol-mismatch probes.

| | Per source | Per window |
| --- | --- | --- |
| benign | 565 | 5,785 |
| malicious automation | 144 | 1,791 |
| **TEMP_BLOCK decisions** | **0** | **0** |
| recall | 0.000 | 0.000 |
| false positive rate | 0.000 | 0.000 |
| **false blocks / 1000 benign** | **0.0** | **0.0** |
| block precision | undefined: nothing was blocked | undefined |
| verdict | `USELESS_NO_DETECTION` | `USELESS_NO_DETECTION` |
| release gate | **FAIL** | **FAIL** |

The false-block number is real and the recall number is real, and only one of
them is good news. A system that never acts has a perfect false-positive rate.

---

## Why: A Units Error, Found by Measurement

The cost model derives its cutoff from the cost ratio:

```
p* = C_FP / (C_FP + C_FN)        public_website: 40 / 41 = 0.9756
```

`p*` is a **probability of maliciousness**: the point at which blocking becomes
the cheaper error. The number being compared against it was `MathRisk`, which is
**an uncalibrated score** and says so in its own module docstring.

Those are not the same kind of number. Comparing them is not conservative, it is
meaningless, and the meaninglessness happened to land on the safe side:

| Conservative estimate on malicious windows | |
| --- | --- |
| median | 0.0000 |
| 90th percentile | 0.0974 |
| maximum | 0.2922 |
| cutoff it had to clear | 0.9756 |

`COST_ALLOW_PREFERRED` and `MARGIN_NOT_MET` appear on **100%** of malicious
windows. The arithmetic never once preferred a block.

P15 described this outcome as "a rare event by construction". The measurement
says *never*, and for a reason nobody had written down. The difference between
"rare" and "never" is the difference between a conservative system and an inert
one, and only running it could tell them apart.

### The Shrinkage Compounds It

`conservative_probability` is exactly **0.0 on 71.8%** of all windows. The
Wilson-style sampling-width term subtracts more than the shrunk estimate whenever
observations are few, and the corpus windows hold 20–40 observations. So most
windows arrive at the cost comparison carrying a zero.

---

## What Was Fixed

`CALIBRATION_UNAVAILABLE` is now a **hard gate** in
`autonomy/authority.py`, not a fallback clause. Without a calibrated probability
the authority refuses to block, and the decision record says so.

This does not make the system detect anything. It converts an accidental
"never blocks, for an unrecorded reason" into a declared "cannot block without
calibration", which is testable, visible in every record, and pinned by
`tests/test_p15_autonomy.py::test_an_uncalibrated_estimate_cannot_block_however_high_it_is`.

It is a strengthening, not a relaxation. §45 forbids solving a model problem by
lowering a gate; this raises one.

---

## Ranking Quality: Where the Evidence Actually Is

If the only problem were the threshold, calibration would fix it. So the
ordering was measured too, does the pipeline rank scanners above ordinary
traffic, threshold aside?

| Evidence stage | per-window ROC-AUC | per-source ROC-AUC |
| --- | --- | --- |
| classifier `model_score` | 0.828 | **0.911** |
| signal diversity | 0.790 | 0.711 |
| anomaly score | 0.782 | 0.652 |
| `MathRisk` (raw) | 0.775 | **0.827** |
| **conservative probability (what decides)** | **0.626** | **0.783** |
| behavioural diversity | 0.551 | 0.475 |

Both columns come from `training.decision_replay.ranking_breakdown`, in the same
run that produced the confusion matrices above, and the table is regenerated by
the command at the end of this report rather than assembled by hand. Sources
aggregate with **max**, which is what the system itself does (a source is
blocked if any of its windows blocks), and the choice is stated because it
changes the numbers. A mean would flatter a stage that is right once and quiet
afterwards, and "right once, quiet afterwards" is the shape of a scanner.

Two findings, both uncomfortable and both useful.

**The decision variable ranks worse than the things it is made of.** Per window
it is second from last, below every upstream stage. Per source it recovers to
0.783 but is still below both of its own inputs (the classifier at 0.911 and
raw `MathRisk` at 0.827), which is the finding that matters: the pipeline
*loses* ordering information at the step that decides. The conservative estimate
is monotone in value but not rank-preserving across sources, because the width
term depends on observation count: a strong source seen briefly is pushed below
a weak source seen at length. That is defensible on the block side (it is what
"conservative" buys), and it means the estimate must not be reused anywhere a
ranking matters.

**Behavioural diversity carries almost no class information** in this corpus
(0.475 per source: very slightly anti-correlated). It is a safety constraint, not
a detector, and it should be read as one. Requiring two behavioural families does
not make a block more likely to be correct here; it makes a block harder, which
is a different and still legitimate goal.

Even at the best available ordering (the classifier's 0.911 per source)
calibration alone would not produce a detector that clears a 0.95 block-precision
bar at useful recall. And that 0.911 is measured on a corpus whose scenario
families the classifier was trained on; on the four families withheld from it,
the same model scores 0.517. **The gap is evidence, not arithmetic.**

## The Corpus

`dataset-eval-v1`, generated for this evaluation by
`dataset/scenarios/matrix-eval-v1.toml`.

```
python -m dataset.cli generate \
  --matrix dataset/scenarios/matrix-eval-v1.toml \
  --output datasets/eval-v1 --dataset-version dataset-eval-v1
```

| | |
| --- | --- |
| rows generated | 7,581 |
| rows scored | 7,576 |
| sources | 709 (565 benign, 144 malicious) |
| scenario definitions | 35 |
| labels | `controlled_scenario`, `trusted_fixture` only |
| dataset SHA-256 | `b8474c2d604d118aeefb99b50a28d8e2a51d5f4b8a8b22fd9b55c17e1df41836` |

It is `matrix-v1` with `runs` scaled (benign ×7, malicious ×2), and nothing
else changed. Two supporting limits moved to allow it: `MAX_RUNS_PER_SCENARIO`
32 → 64, and the source pool gained the third RFC 5737 documentation range
(762 addresses). Both are recorded in `dataset/scenarios/__init__.py` with the
reason.

**This buys statistical power and no coverage.** Scenario diversity is unchanged
at 35 definitions. The false-block rate is estimated over *these behaviours*, not
over the Internet.

### Excluded, and Why

| Reason | Rows |
| --- | --- |
| identical feature vector appears under both labels | 5 |

Two vectors in the corpus carry conflicting labels. A benign session and a slow
scan that produce byte-identical bounded windows. At that resolution ground truth
does not exist, so scoring them either way would move a metric without measuring
anything. `dataset/validator.py` reports the same vectors as a critical finding,
which is where this was noticed.

Rows labelled `unlabeled` never entered: §5 forbids inferring a label, and the
schema forbids constructing one from a decision this system made.

`hard-negative-health-check`, `hard-negative-monitoring`, `hard-negative-admin`,
`hard-negative-discovery`, `hard-negative-connect`, `hard-negative-deception`,
plus `benign-api`, `benign-web`, `benign-web-burst`, `benign-ssh`,
`benign-retry`, `benign-noise`, `benign-truncated`, `live-benign-client`,
`live-benign-health`.

Health checks, monitoring probes, service discovery, API clients, asset bursts,
administrator diagnostics, backup-shaped clients, retry storms and truncated
sessions. **None was blocked.**

### Hard Positives (§9)

`scan-sequential`, `scan-randomized`, `scan-slow`, `scan-burst`,
`scan-horizontal`, `scan-connect`, `probe-enumeration`, `probe-repeated`,
`probe-truncated`, `credential-automation`, `credential-low-rate`,

Sequential, random, slow and burst scans; HTTP and service enumeration;
credential automation at full and low rate; multi-stage reconnaissance; decoy

## How It Was Replayed

`training/decision_replay.py`. Every row goes through the real components in the
real order: `MathRiskEngine`, the ONNX classifier in its isolated subprocess,
the Isolation Forest anomaly model, `OODEngine` against the shipped reference
distribution, `DataQualityResult`, `DecisionFusion`, `PolicyGuard`, and
`AutonomousDecisionAuthority`. Nothing is re-implemented.

Three assumptions, all of which make the measurement **harder**, not easier:

1. **Every source is directly connected**: identity HIGH, network-enforceable,
   scope `NETWORK_SOURCE`. The identity gates that refuse a CDN client are the
   cheapest possible way to look good on a false-block metric, so they are
   switched off. Every block had to be won on evidence.
2. **Every source is replayed cold**, `offence_count = 0`. No decision gets the
   lower repeat-offender margin.
3. **Labels come from the corpus and nowhere else.** No self-labelling, no
   `blocked = malicious`, no `model_score = label`.

Run with and without classifier authority. The results are identical, because the
calibration gate refuses before the classifier can matter.

## Bootstrap Intervals

Computed and reported in `P15_1_DECISION_EVALUATION.json`. With zero blocks the
interesting statistics are degenerate: block precision is undefined in every
resample, and the false-block rate is 0.0 in every resample. That is what a
seeded percentile bootstrap over 7,576 rows of a system that never acts looks
like, and printing it as though it were a useful interval would be theatre.

---

## What This Means for the Gates

**Gate C, ML validity: FAIL.** §37 offers two routes. The classifier is not
validated: its own manifest says `quality_gate_passed: false`, and its
generalisation section reports ROC-AUC **0.517** on the four withheld scenario
families, chance. The second route, "operates without classifier authority
using a validated deterministic fallback", needs the fallback to be *validated*,
and a fallback measured at recall 0.000 is inert rather than validated.

**Gate E, false-positive safety: FAIL.** Now measured rather than
unmeasurable, on 565 trusted benign sources and 144 trusted positives, which
clears the 500/50 minimum. False blocks per 1000 benign: **0.0**. Block
precision: **undefined**, because block precision of an empty set is not a
number. §38 requires both measured; one of them cannot exist yet.

## Reproducing This

```
python -m dataset generate --matrix dataset/scenarios/matrix-eval-v1.toml \
    --output datasets/eval-v1 --dataset-version dataset-eval-v1
python -m training.decision_replay_cli \
    --corpus datasets/eval-v1/processed/dataset-eval-v1/samples.csv \
    --json reports/P15_1_DECISION_EVALUATION.json
```

The corpus is 24 MB of generated traffic and is deliberately not committed; the
recipe that produces it is. `reports/P15_1_DECISION_EVALUATION.json` is the raw
output of the second command, and every number in this report comes from it.

The corpus is deterministic from its seeds and the replay holds no state, so the
numbers above are reproducible from a clean checkout.
