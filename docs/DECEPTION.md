# Deception

Eye for an Eye can open decoy TCP ports. A decoy answers like a simple service
and records what the visitor does. This is called **defensive deception**.

Status: **Beta.** The Linux redirect mode is **NOT VERIFIED IN CURRENT
ENVIRONMENT**.

## Why Do This

* It slows down automatic scanning.
* It collects behaviour data about the scanner.
* It separates a real bot from a normal user, because normal users do not talk
  to a port that no real service uses.
* It gives an attacker a false picture of your machine.

## There Is No Hack-back

This is a hard rule in the code, not a policy in a document.

The system never attacks anyone. There is no counter-scan, no exploit, no
denial of service, and no attempt to crash the visitor's tool.

The visitor never gets:

* a shell,
* command execution,
* an executable file,
* a proxy,
* a connection back to their machine.

If you read older project documents that talk about attacking back, they are
**historical** and are not the current design. See `docs/history/`.

## What a Decoy Can Say

There are three reviewed, fixed profiles in catalogue version 2:

| Profile | Protocol | What it imitates |
| --- | --- | --- |
| `ssh-banner-v2` | TCP | An SSH identification banner |
| `ftp-control-v2` | TCP | An FTP control channel |
| `http-static-v2` | TCP | A small static HTTP server |

Answers come from this fixed catalogue. Nothing is generated from a scanner
signature database at run time, and nothing is generated by a language model.

```sh
eye-for-an-eye profiles list
eye-for-an-eye profiles show ssh-banner-v2
```

## How a Session Works

```text
Accepted TCP socket
      -> destination and response policy
      -> one immutable selected profile
      -> a finite protocol session (in memory)
      -> cumulative byte limits, then send
      -> safe interaction events
      -> the normal bounded event queue
```

* One server owns the socket and every deadline.
* One bounded buffer per connection. No extra thread per client.
* State is deleted and the buffer is cleared when the connection closes.
* There is no separate, unbounded table of sources or sessions.

Having a profile does not switch off the global limits. Admission, load and rate
are checked again for every answer, and the current policy is checked again just
before writing to the socket. If the event queue rejects telemetry, the engine
falls back to observe-only for a while.

## Who May Reach a Decoy

`deception.source_allowlist` is `["127.0.0.0/8", "::1/128"]` by default. An
empty list allows nobody.

In `lab` mode the rules are stricter: the listener must bind loopback, and the
allowed source range must be a non-global IPv4 `/24` or IPv6 `/120` or narrower.

## Which Ports

| `port_set` | Ports |
| --- | --- |
| `common` | 21, 80, 2222, 8080 |
| `extended` | 21, 80, 2222, 8080, 2121, 2200, 8000, 8888 |
| `custom` | your `decoy_ports`; an empty list means `network.port` |

These sets decide which profile may be chosen. They do **not** open many sockets
and they do **not** apply firewall rules. A direct listener serves one port.
Redirection is a separate, namespace-only firewall feature.

Well-known FTP, HTTP and SSH ports limit the profile family. Other custom ports
choose a profile with an HMAC over the whole catalogue, so the choice is stable
but not guessable. `deception.port_profiles` can pin a family for a port:

```toml
[deception.port_profiles]
"1234" = "http"
```

A configuration that puts a decoy on a protected port is rejected. The listener
also refuses to bind a real service port or a management port. Real services
always win.

## Direct Mode and Redirect Mode

* **Direct**: the decoy uses its own local socket endpoint. This works today.
* **Redirected**: the decoy asks the kernel for the original destination
  (`SO_ORIGINAL_DST`, Linux IPv4 TCP only). On any failure (unknown address or
  port, IPv6, or UDP) the result is `UNKNOWN` and the session becomes
  observe-only. There is no fallback to the listener endpoint when redirect is
  required.

Actual Linux redirect is **NOT VERIFIED IN CURRENT ENVIRONMENT**.

## What Is Recorded

Metadata only:

* which profile answered,
* how many messages and transitions,
* payload length as a number,
* whether the attempt looked like a login (`credential_like_attempt`).

Not recorded: the payload itself, the username, the password. The default
`username_policy` is `redact` and `preview_enabled` is `false`.

## The Secret

Honeypot and lab profiles use a persistent 32-byte secret. `eye-for-an-eye
setup` creates it once, with file mode `0600` on POSIX systems. It is never
overwritten and never printed. `*.secret` is in `.gitignore`.

If you lose it, profile selection changes. If you leak it, an attacker can
predict which decoy answers on which port.

## Turning It Off

```toml
[deception]
enabled = false
```

A passive sensor never serves a decoy, whatever this setting says, because it
has no listener.
