# Data and Models

What is bundled with this software, where it came from, and what it is allowed
to do.

## The Short Version

Every model artifact in this repository was fitted on **synthetic data**
generated by tooling in this repository. None of it was trained on real traffic
from anybody's deployment, and none of it was trained on traffic from yours.
This is the main thing to know when reading any number a model produces.

## What Ships

| Artifact | Format | What it is |
|---|---|---|
| `models/risk-logreg-v1.onnx` | ONNX | the auxiliary risk model |
| `models/isolation-v1.onnx` | ONNX | the anomaly model |
| `models/mathrisk-cal-v4-*.json` | JSON | calibrators mapping a MathRisk score to a probability |
| `models/classifier-cal-v1-*.json` | JSON | calibrators for the auxiliary classifier |
| `models/*-manifest`, `*.json` sidecars | JSON | the metadata below |
| `models/MODEL_CARD_risk-logreg-v1.md` | Markdown | the model card |

**No pickle, no joblib.** Loading either executes whatever the file contains,
and a defensive tool that can be made to run arbitrary code by replacing a data
file is not a defensive tool. This is a standing rule rather than a current
state of affairs.

## What a Manifest Records

Every bundled model has one, and the loader refuses the model without it:

* the model name and version;
* the feature schema version it is bound to, and the exact feature order;
* the input shape and dtype;
* a SHA-256 of the model file;
* the quality gate result and the authority the artifact is recommended for.

The loader checks the hash before use, checks that the feature order matches
the schema the manifest names, and **refuses an artifact whose ownership or
permissions would let another account modify it.** That last check surprises
people: a calibrator copied with a group-writable mode is reported as
unavailable rather than loaded. Work with a `umask` of `022`.

A manifest whose feature schema version this build does not serve is refused
rather than read against the wrong column names. A model that predicts using
the wrong column order is not a degraded model; it is a confident wrong answer,
which is worse.

## What a Model Is Allowed to Do

An auxiliary model is **evidence**, never authority. Its score is one input
among several, and it cannot reach an enforcement action on its own. Every
decision still passes through evidence maturity, the cost model, and
PolicyGuard, in that order, whatever the model said.

If the model fails to load or fails at inference, the deterministic path
continues and the component health reports the failure. `ml.required = false`
in both production profiles is what makes that the behaviour rather than a
crash.

An ML score is not a probability. The calibrator is what turns a score into
one, and without a calibrator the authority has no probability to price a
decision with, so it refuses to block rather than guessing.

## Training Data

The corpora are **not published**. They are generated, they are large (about
710 MB), and they are reproducible from what is here:

* `dataset/` holds the schema, the validators and the generators;
* `training/` holds the training, replay and evaluation tooling;
* `datasets/*/dataset_manifest.json`-style records pin a corpus by SHA-256 so a
  rebuild can be checked against the one a model was fitted on.

Rebuilding is a documented operation rather than an implied one; see
[DATASET.md](DATASET.md) and [MODEL_TRAINING.md](MODEL_TRAINING.md).

## Labels

A label may come from a controlled scenario, a signed capture sidecar, a
deterministic harness, or a reviewed evaluation. It may never come from the
system's own output.

Specifically, none of these is ever used as a training label: a block, an
allow, a model score, a MathRisk score, or a failed challenge. A model trained
on its own decisions learns to agree with itself, and a benchmark built the
same way can never disagree with the thing it measures.

## Captured Traffic

The only capture files here are small synthetic fixtures under
`tests/fixtures/`, written by `tests/fixtures/p2/generate.py`. That generator
writes only inside its own directory, records a SHA-256 for each file, and
marks the manifest `synthetic`. They exist so the offline analysis path has
something to parse in a test.

No real traffic is published. A deployment's own decision journal and shadow
export are its own: they are pseudonymous, and pseudonymous is not anonymous.
