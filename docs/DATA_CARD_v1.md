## Purpose

A dataset for a local behavioural risk model, built so that Logistic Regression, Gradient
Boosting and other tabular candidates can be trained and compared on identical rows, an identical
feature contract and an identical honest split - and so that the limits of that comparison are
written down before anyone reads an accuracy number. No model is trained in this phase.

The dataset teaches behaviour, not identity. No address, port, ASN, provider, country, hostname,
username, capture name, scenario name, sensor id or grouping key is a model feature, and no
decision this system made is a label or a feature.

## Sources

Three sources with different roles, kept distinguishable and never treated as equivalent.

| source | rows | role | label authority |
|---|---|---|---|
| LAB | 1674 | high label confidence, lower realism | scenario intent, decided before generation |
| PCAP | 343 | packet-level realism | the sidecar beside each capture |
| SHADOW_UNLABELED | 317 | deployment realism, no ground truth | none |
| SHADOW_REVIEWED | 0 | the only shadow rows eligible for training | manual review |

### LAB generation

158 scenario runs across 31 families, rendered as small captures and read back through the
production packet parser, plus 191 rows from event-mode scenarios the capture path cannot express
(decoy interaction, connect-only probing), plus 4 live loopback runs against the real sensor.

Live runs open real TCP connections to `SelectorServer` and `DeceptionEngine` bound on 127.0.0.1.
Production config validation refuses deception `mode = lab` unless the bind address is loopback
and the source allowlist is narrow and non-global, so a run that is not local does not start.
Every scenario also carries hard bounds on duration, connections, packets, bytes, concurrency,
destinations and samples, and a scenario without bounds does not run.

Coverage: ordinary benign clients, hard negatives (monitoring, load-balancer health checks,
TCP-connect probes, administrator diagnostics over 3/5/10 ports, service discovery, benign decoy
contact), malicious automation (sequential, randomised, horizontal and connect scans, repeated
probes, service enumeration, protocol mismatch, credential-shaped automation, decoy enumeration,
multi-stage reconnaissance) and hard positives (slow scans, burst-and-pause, low-rate credential
attempts).

### PCAP collection

12 captures: 10 generated by a separate packet-level generator that varies TTL, IP ID, TCP
options, window size, segmentation, retransmission and delivery order and includes one IPv6
capture and one recorded at a 44-byte snaplen, plus 2 capture fixtures that already existed in
this repository before the dataset work started.

Every label comes from the sidecar manifest beside the capture. A file name never decides a
label. Two captures are deliberately UNLABELED, because a capture without trusted provenance is
better left unlabelled than guessed at. All windows from one capture share one `capture_group`, so
a capture never straddles a split.

### Shadow collection

A sanitised pool of 317 rows over 14 pseudonymous sources, produced by observing a mixed workload
with the sensor and exporting only the FeatureVector and bounded metadata. It is a **synthetic
stand-in**: no real deployment has produced telemetry for this project yet, and the manifest says
so rather than implying otherwise.

Collection is bounded in every dimension - maximum samples, maximum output bytes, flush interval,
raw retention - and stops cleanly rather than growing.

## Labels

`benign_like` and `malicious_automation_like` for the supervised classes; `uncertain` and
`unlabeled` exist as first-class states. A label describes observed behaviour in one window, not a
person, an intent or a confirmed attack. The positive class is deliberately not called "hacker",
"attack" or "attacker".

`label_source` records where a label came from: `controlled_scenario`, `trusted_fixture`,
`manual_review`, `synthetic_generator` for supervised rows, and `shadow_observation` or
`unlabelled_capture` for rows that carry no label at all. A shadow decision, a risk score, a fused
score, an action, a firewall state or an earlier model is refused as a label source by the sample
constructor, by the loader and by the validator.

`label_confidence` is HIGH only for deterministic controlled ground truth. Capture fixtures and
the IPv6 and truncated captures are MEDIUM. Everything unlabelled is LOW.

Manual review is available and exercised by tests, but nobody has reviewed anything yet, so
`SHADOW_REVIEWED` is 0. A reviewed label carries its annotation, its confidence and its review
timestamp; the reviewer's identity is deliberately not part of the dataset. A reviewer may always
answer `uncertain`, and uncertain rows stay out of supervised training.

## Privacy

The processed dataset contains no address of any kind. Every address in the raw material is a
documentation-range placeholder or loopback; every payload is a synthetic string written by this
repository; no credential, password, cookie, token or command from any real system exists here.
The credential-shaped requests are `USER lab`, `AUTH lab` and `LOGIN lab`, and only their count
reaches a feature.

Shadow export is default deny: only an allowlist of bounded numbers, flags and short enumerations
survives, and payload, headers, credentials, cookies, tokens, command text and keyed payload
digests are dropped. Sources are grouped by a pseudonymous identifier - HMAC under a local secret
for a real export, a fixed salt for this synthetic pool because it contains no real address - and
the raw address is not kept after grouping. The secret is never committed and never written into
an export; `datasets/unlabeled/` and `*.dataset-secret` are git-ignored.

Raw captures live under `datasets/raw/` and are separate artifacts from the processed
FeatureVectors. No production capture is committed to this repository.

## Retention

Raw shadow telemetry has a configurable retention (30 days in this build) and is discarded on that
schedule. The sanitised FeatureVector pool may be kept longer, because it carries no content. Raw
network content is not retained on the grounds that a model might want it later.

## Feature schema

34 model features of the 36-column production tensor: 17 behavioural values and their 17
availability masks. `previous_risk` and its mask are excluded from fitting because training on
this system's own earlier output closes a feedback loop. `datasets/model_features_v1.json` carries
the ordered list, the reason each feature is included, and 44 named columns that may never become
model input with the reason for each - identity leakage, label leakage, decision feedback or bias.

Rows and runtime tensors both come from `eye_for_an_eye.decision.features`. There is no
training-only feature extractor to keep in step with the production one.

## Train / validation / test methodology

Correlated rows never cross a split, and which key holds them together depends on the source: a
LAB scenario run, a whole PCAP capture, a pseudonymous shadow source. Unreviewed shadow telemetry
is not split at all.

Whole scenario families and whole captures are withheld from training - slow scanning, low-rate
credential attempts, high-rate health checking, administrator diagnostics and two held-out
captures in test; burst scanning, service discovery and one capture in validation. The remaining
families are bucketed by group so every split keeps representative data from both classes.

Train 1001 rows / 80 groups, validation 427 / 34, test 554 / 53. The test split is frozen with a
SHA-256 per file. If it influences model selection, the correct response is a new dataset version
with a new holdout, not a re-split.

## Known biases

**LAB.** Synthetic behaviour from one generator family in one lab topology. Timing is generated,
not observed. Protocol coverage is HTTP, SSH, FTP, a Redis-shaped probe and a few binary probes.
Scanners here vary their probes more than real tools often do, which makes `repetition_60s`
separate the classes more cleanly than it deserves to be trusted in production. Live loopback runs
are few and short, because real time cannot be compressed.

**PCAP.** Project-owned synthetic captures plus two pre-existing contract fixtures. Realism is
packet-level - TTL, TCP options, window sizes, segmentation, retransmission, reordering, one IPv6
capture - not population-level. There is no packet loss beyond what is generated deliberately, one
lab topology, and label reliability rests entirely on sidecars this project wrote. The two
fixtures were built as correlation contract tests, not as dataset samples, so their confidence is
MEDIUM.

**SHADOW.** A synthetic stand-in for telemetry no deployment has produced. Sensor placement,
traffic population and time period are all invented. Manual review coverage is zero. Its value
here is a distribution to compare against and a review queue to work through, not realism that has
been observed.

**Across sources.** Class balance is near even, which a real sensor never is. Both labelled
sources carry both labels, so source type cannot stand in for the label, but shadow rows are
identifiable from `destinations_60s` at AUC 0.921 - an environment artefact that must be checked
again before any reviewed shadow row is trained on.

## Known gaps

- Reviewed shadow rows: 0. The highest-realism source contributes no labels.
- No real capture, no real environment, no adversary adapting to us.
- Nine availability masks never vary, so nothing is learned about missing counts or timing.
- No UDP, no fragmentation, no TLS handshake behaviour, no distributed multi-source campaign.
- Positive behaviour comes from two related generators; cross-tool generalisation is untested.
- Effective sample size is 182 groups, not 2334 rows.

## Intended use

- Fitting and comparing local behavioural risk baselines for Eye for an Eye.
- Shadow-mode evaluation and offline experimentation.
- Regression testing the feature pipeline: a change in the parser, the windowing or the extractor
  shows up as a change in these rows.

## Not intended use

This dataset does **not** support and must not be used for:

- identifying a person, an operator or an organisation;
- attributing an attack to an actor, a country or a network;
- geolocation, reputation scoring or any Internet-wide blocklist;
- malware classification, exploit detection or intrusion confirmation;
- automatic blocking decisions, or any claim that a model fitted here is production ready;
- benchmarking against real-world traffic, which it does not represent.

## Maintenance

Versioned semantically: a change to the feature schema, the labels, the scenario or capture set,
the split, or a generator bug fix requires a new dataset version. Raw captures, live traces, the
shadow pool, the dataset manifest and the split manifest each carry SHA-256 values, and a build
refuses to run against raw material that changed since ingestion.

Reproduce with `python -m dataset build --lab --pcap --shadow`; validate an existing release with
`python -m dataset validate`. Both are offline and neither writes runtime configuration. A
generator defect is a code defect and belongs in the same tracker as the rest of the code.
